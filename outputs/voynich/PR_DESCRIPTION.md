## Lexer extension (new in this PR)

The probe previously tokenised at the per-character level (`tokens_char`), which
collapsed EVA ligatures into single letters (e.g. `aiin` → 4 chars; `chol` → 4 chars;
`cthol` → 5 chars). This PR adds a **greedy longest-match EVA glyph lexer** that
splits each word into canonical EVA atoms:

| Glyph (ligature) | Source | Example word | Result |
|---|---|---|---|
| `aiin` (4-letter quadryll) | Takahashi | `daiin` | `[d, aiin]` |
| `dain` (4-letter quadryll) | Takahashi | `dain`  | `[dain]` |
| `cth`  (3-letter triglyph)  | Takahashi | `cthol` | `[cth, o, l]` |
| `ch`   (2-letter digraph)   | EVA std.  | `chol`  | `[ch, o, l]` |
| `sh`   (2-letter digraph)   | EVA std.  | `shol`  | `[sh, o, l]` |

Lexicon lives in `tools/scripts/voynich_probe.py :: EVA_EXTENDED_GLYPHS`,
asserted sorted-by-length-descending at module load so the greedy matcher
cannot regress on ordering. Vowel+r digraphs (`ol`, `or`, `ar`, …) were
**pruned** because they overlap with per-char sequences in real ZL3b-n
words (`chol` → `ch` + `o` + `l`, not `ch` + `ol`).

The parser returns a third stream `tokens_glyph` alongside the existing
`tokens_word` and `tokens_char`. `morphology_block` runs the same
`symbolseq.structured_vs_shuffled` machinery on the glyph stream,
producing a new `glyph_level` block in `morphology`. The verdict adds one
read-only invariant — `voynich_glyph_structured` — alongside the existing
`voynich_word_structured` + `voynich_char_structured`; it does **not**
change the verdict-name logic.

Glyph-level metrics are reported in NOTES.md (a third Morphology row in
the Correlations table; a Top-glyph-bigrams list) and in `run.json`
(`morphology.glyph_level.*`, `n_tokens_glyph`, `n_distinct_glyph`,
`top_glyph_bigrams`, `verdict_block.invariants.voynich_glyph_structured`).

## Probe pipeline

1. `parse_zl_ivtff` strips `<!...>` operators, `{...}` annotations, `<$>` / `<->`, `[a:b]` → `a`, leading `?`. Per-line word list + flat char token stream + flat **glyph** token stream (greedy longest-match through `EVA_EXTENDED_GLYPHS`) + folio IDs.
2. `morphology_block` runs `symbolseq.structured_vs_shuffled` (n=1000) on **three** streams — word, char, and glyph — with the same `z<-3` structured-floor.
3. `plant_voynichese_like` (PLANT_SELF_LOOP Markov) and `plant_latin_like` (in-house Latin Markov over 60+ synthetic words) as known-answer positive controls with constant thresholds: `PLANT_VOYNICHESE_THRESHOLD=-3.0`, `LATIN_PLANT_THRESHOLD=-1.5`.
4. `dominik_rho_claim_block` recomputes Spearman rank-correlation between top-N (default 200) Voynich character bigrams and the embedded 24-entry Semitic-triliteral romanisations (k-t-b, s-l-m, etc.), vs a 1000-round unigram-preserving shuffle null. DOES NOT bundle Dominik's packaged JSON; reports the abstract ρ≈0.82 + packaged ρ≈0.9999 mismatch for transparency only.

## Verdict logic

| Tier | Condition | Verdict |
|------|-----------|---------|
| 1 (known-answer) | plant + Latin controls FAIL | `UNDERDETERMINED` |
| 2 (real data) | both word and char structured | structure_level = `FULL` |
| 2 (real data) | only word or only char structured | structure_level = `PARTIAL` |
| 2 (real data) | neither structured | `NO_SIGNAL` |
| 3 (claim) | ρ fails unigram-preserving shuffle null by ≤+2σ | `CLAIM_FAILS_NULL` |
| 3 (claim) | ρ beats null by ≥+2σ but packaged-JSON ρ≠abstract | `RHO_PENDING_INDEPENDENT_RECHECK` |

The `voynich_glyph_structured` invariant is computed alongside `voynich_word_structured` and `voynich_char_structured` for cross-stream consistency; it is **read-only** and does **not** influence the verdict name.

This regression landed verdict: `SEQUENCE_STRUCTURE | CLAIM_FAILS_NULL`,
with glyph-level z consistent with the broader morphology tier.

## Forbidden-phrase guard

- `assert_no_forbidden_phrases` scans ONLY prose paths (`stance`, `caveat`, `dominik_claim_note`, `verdict_block.notes`, etc.). Machinery fields (the `forbidden_phrases` LIST itself, structural counters, IDs) are EXEMPT, otherwise listing banned phrases would always trip the guard.
- `write_notes_md` returns `(body, log_section)` so the explicit forbidden-phrase enumeration is in `log_section` (audit surface) and the guard scans only `body` (free-form prose).
- Motto hyphenated "no viral-blog as truth" to avoid a literal `"viral blog"` substring match.
- Known limitation: the substring matcher can't catch paraphrases. The README documents this. A human reviewer remains the final arbiter.
