# data/geo/amazon_lidar_neg — Synthetic LiDAR negative / control tiles

This directory holds synthetic negative and control tiles for the Amazon
LiDAR hardening probe (`tools/geo/lidar_negative_probe.py`). No real canopy
LiDAR, DEM, or point-cloud data is committed here — these are purely synthetic
masks used to calibrate false-positive rates.

## Contents

| File | Description |
|------|-------------|
| `tiles.json` | Archive of sample control tiles (CSR, forest, scramble, planted) generated by `lidar_negative_probe.py`. |

## Tile kinds

- **csr** — Independent Bernoulli masks. These are Complete Spatial Randomness
  negatives: no spatial structure at all.
- **forest** — Smoothed random-field masks thresholded to the target density.
  They mimic the patchy, low-frequency texture of canopy/terrain returns where no
  geoglyph is present.
- **scramble** — Pixel-wise shuffles of the `planted` masks. Density is preserved
  but straight-line structure is destroyed.
- **planted** — Synthetic straight-line geoglyphs (a square enclosure plus a
  diagonal cross). These are the known-answer positives used to validate that the
  detector can fire on real structure.

## Generation

Sample tiles are written deterministically when the probe is run:

```bash
python tools/geo/lidar_negative_probe.py --data-dir data/geo/amazon_lidar_neg
```

Parameters are recorded in each tile record:
- `kind` — tile class
- `shape` — tile height/width in pixels
- `density` — target foreground fraction
- `seed` — seed used to generate that tile
- `mask` — binary mask encoded as strings of `'0'`/`'1'`

## Stance / caveats

- These tiles are synthetic; they do **not** represent real Amazon LiDAR data.
- No public dense LiDAR/DEM tile for a named Amazon geoglyph was located.
- A calibrated false-positive rate on these masks does not imply that any real
  geoglyph signal exists.
- Structure detection ≠ message, intent, or lost civilisation.
